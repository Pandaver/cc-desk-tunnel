# 外部推送

用浏览器下发任务、或人不在电脑前时，Windows 的系统通知看不到。外部推送由服务端把会话的通知发到聊天机器人或手机应用，不需要任何客户端在线。

## 设置

在「设置 → 外部推送」里：

1. 打开「开启外部推送」。
2. 「添加渠道」，选类型并填写机器人或应用给出的地址、密钥，然后点「测试」确认能收到。
3. 回到会话，在输入框下方审批模式旁边的铃铛里订阅这个会话。

设置保存在服务端（数据目录的 `push.json`），对所有连接到它的设备生效。没有开启、或没有启用的渠道时，铃铛不显示。

| 渠道 | 需要填写 |
| --- | --- |
| 钉钉机器人 | 机器人的 Webhook 地址；安全设置选“加签”时填密钥，选“自定义关键词”时可用“任务”“审批”等字样 |
| 飞书机器人 | Webhook 地址；开启签名校验时填密钥 |
| 企业微信群机器人 | Webhook 地址 |
| Telegram Bot | Bot Token 与 Chat ID |
| Bark | App 里显示的地址，形如 `https://api.day.app/<Key>` |
| 通用 Webhook | 地址，以及可选的 JSON 请求体；`{{title}}`、`{{text}}`、`{{url}}` 换成标题、内容和会话链接。有请求体时发 POST，没有时对地址发 GET。Server酱、PushPlus、ntfy、Gotify 等都可以这样接入 |

渠道添加后不再显示地址和密钥，浏览器也读不到；要修改就删除后重新添加。

## 订阅

| 铃铛 | 推送什么 |
| --- | --- |
| 不订阅 | 不推送（除非开了下面的“未订阅的会话也推送审批和提问”） |
| 本轮 | 正在进行的这一轮、没有运行时则是下一轮：其间的审批、提问和它的结束。这一轮彻底结束后自动回到“不订阅” |
| 持续 | 这个会话之后每一轮的通知，直到改回“不订阅” |

- 订阅属于会话，桌面和浏览器看到、改的是同一个；已订阅的会话在侧栏标题旁显示同样的铃铛。
- 「新会话默认订阅」决定新建和分叉出的会话从“不订阅”还是“持续”开始；分叉不继承原会话的订阅。
- 推哪些事（等待审批、Claude 提问、任务完成、任务失败）对所有会话统一设置。主动停止的一轮不推送“完成”。
- 只剩后台任务时不推送“完成”，“本轮”订阅也不结束：Claude 在这里多半是在等构建或测试，任务结束后会自己接着做，真正做完才推送。这与窗口的系统通知不同，后者在只剩后台任务时就提醒。用后台命令一直挂着的服务（运行不会结束）因此不会推送“完成”，其间的审批和提问照常推送。
- 「未订阅的会话也推送审批和提问」：会话卡在等你回答时，没订阅也推送。可以设「延迟推送」，等待这么久仍没有在任何窗口处理才推送；订阅过的会话总是立即推送。
- 在 `ccdt` 终端里进行的轮次、服务端自己的空闲压缩不推送。

## 内容与隐私

推送只包含事件、会话标题和会话所在的设备名；失败时附上错误信息。不含 Claude 的回复、命令输出或文件内容。服务端开启了[浏览器访问](server-web.md)时，消息里带一个“打开会话”的链接，点开直接进入这个会话；地址本身不写在消息里。

这些内容会经过所选渠道的服务商。每个渠道最后一次发送失败的时间和原因显示在设置页，同时记在服务端日志里；失败不影响任务。

## 权限

| 操作 | 桌面客户端 | 浏览器 |
| --- | --- | --- |
| 添加、删除渠道 | ✓ | — |
| 启用或停用渠道、测试 | ✓ | ✓ |
| 总开关、推哪些事、默认订阅、未订阅的会话与延迟 | ✓ | ✓ |
| 订阅会话 | ✓ | ✓ |
