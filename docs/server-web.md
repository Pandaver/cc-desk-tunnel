# 服务端 Web 客户端（实验性）

浏览器直接连接现有服务端，使用与桌面客户端相同的页面、组件和业务协议。服务端提供静态页面和浏览器登录，不再托管桌面工作台的镜像，也不转发桌面的 HTTP 服务。

```text
浏览器 ── HTTPS / WSS ── 服务端 ── 现有执行通道 ── 目标设备
桌面端 ───── WSS ──────┘
```

浏览器和桌面独立选择会话、保存草稿和滚动位置；会话消息、审批和运行状态仍由服务端同步。关闭浏览器或退出浏览器登录不会关闭桌面客户端的连接。操作本地项目仍需要目标设备在线，不是脱离设备的纯云端执行。

## 当前支持

- 查看现有设备、项目与会话，以及会话消息和执行进度。
- 在已有会话中发送消息、回答问题、审批、停止，以及打开目标设备的原生终端。
- 与桌面共用界面和业务命令；浏览器不提供本机目录选择、执行通道、窗口管理和客户端升级等桌面宿主能力。

第一版不提供浏览器新建或移动项目、创建或分叉会话、附件上传和定时任务管理。它们需要明确的目标设备接口或文件传递机制，不通过让浏览器冒充执行设备实现。原桌面功能保持原有路径。

## 启用

Web 入口默认关闭，每次服务端启动后都需要在桌面设置中明确开启。关闭时不创建浏览器授权管理器、定时器或页面、登录、WebSocket 入口；普通桌面连接保持原有路径。不增加容器或监听端口；沿用现有服务端端口，默认 `8787`。

在部署数据目录的 `config/service.env` 中添加公开访问的**准确来源**，不要带结尾斜杠、路径、查询参数或用户凭据：

```dotenv
PROXY_WEB_ORIGIN='https://proxy.example.com'
```

首次配置来源后执行原有重启命令，让服务端具备 Web 访问能力：

```sh
sudo bash deploy/manage.sh restart
```

然后在已连接的桌面客户端中打开“设置 → 常规 → 浏览器访问”，开启“启用 Web 访问”。来源配置本身不会自动启用入口；日常开关无需重启服务端，不中断桌面连接或执行中的任务。未配置来源时不显示这块设置。

这里编辑的是数据目录的 `config/service.env`，不是程序目录的 `.local/docker.env`。入口地址用于核对浏览器来源，不负责申请证书、配置 DNS 或修改防火墙。公网与局域网访问要求浏览器信任的 HTTPS；可以沿用已有可信证书或 NGINX。桌面指纹连接的自签名证书不会自动成为浏览器信任的证书。

直接 TLS 模式可将来源设为 `https://proxy.example.com:8787`，并使用匹配该主机名的可信证书。NGINX 模式保持 `PROXY_TLS_MODE='reverse-proxy'`，容器端口仍仅绑定宿主回环地址。

### NGINX

先完成 [NGINX 部署](../deploy/nginx.md)。保留原有 `/ws`、`/client/installer` 和 `/health` 配置，在同一个 HTTPS `server` 中增加浏览器 WebSocket 路径，并将原来返回 404 的 `location /` 替换为：

```nginx
location = /web/ws {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $cc_desk_tunnel_connection;
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
    proxy_buffering off;
}

location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_buffering off;
}
```

`$cc_desk_tunnel_connection` 使用现有示例的 `map`。不要重写路径，也不要为浏览器入口开启跨域访问；页面、登录请求和 WebSocket 使用同一个来源。第一版不支持挂载在 `/some-prefix/` 子路径下。

## 登录与撤销

1. 使用已连接的桌面客户端，在设置中的“浏览器访问”开启入口，客户端会自动准备一次性配对码。
2. 复制服务端访问地址，在浏览器输入配对码；也可以直接使用桌面上的打开图标。
3. 开启入口或进入这块设置时，没有有效码就自动生成；已有有效码直接复用，不延长其有效期。配对码有效期 5 分钟，使用一次后失效。浏览器取得独立登录，不接收或保存服务凭据 `PROXY_TOKEN`；服务端不设置登录自动过期。
4. 在桌面的“已登录浏览器”中可以展开列表并单独撤销；配对、退出、撤销与码失效会同步更新，不需要反复刷新。退出登录、撤销或浏览器清理登录数据后需重新配对；退出或撤销也会关闭已经建立的浏览器连接。

配对码只在明确进入设置或启用入口时按需准备，不在后台循环续码。生成失败会显示错误，重试由用户发起；手动重新生成仍需确认。

浏览器登录代表对该服务端已有会话的操作权限，不是仅限于生成配对码的那台桌面。请只给自己的可信浏览器配对。Cookie 为 `HttpOnly`、同站点且在 HTTPS 下使用 `Secure`；服务端只保存登录凭据的哈希。登录、退出和 WebSocket 握手检查来源，失败配对限速；桌面服务凭据认证路径保持不变。

关闭“启用 Web 访问”会立即停止整个服务端的浏览器入口、断开浏览器连接并清除未使用的配对码，不影响原有桌面连接和会话任务。浏览器打开的原生终端随连接关闭，桌面端的终端不受影响。配置、项目、会话和浏览器授权记录仍保留；重新开启后，未撤销且仍保留登录数据的浏览器可以继续使用。所有已打开该设置的桌面同步开关与授权状态，配对码只发送给生成它的桌面设备。服务端重启后入口恢复关闭，需要再次明确启用。

Web 配置或授权文件读取失败只会让本次启用失败，不阻止普通代理服务启动。取消 `PROXY_WEB_ORIGIN` 并重启可移除该可选能力。旧版服务端只有部署时开关时，客户端保留其原有配对管理入口，不显示不受支持的动态开关；未声明幂等初始化能力的服务端仍使用手动生成，避免重置已有配对码。

## 连接诊断

支持诊断的服务端会在桌面和浏览器的标题栏提供“连接诊断”入口。手动测试通过当前已认证的 WebSocket 连续采样 5 次，以中位数显示服务往返耗时；展开详情可查看每次采样、最小值、最大值及超时或失败次数。不会定时或在后台自动测试。

浏览器测量的是浏览器到服务端的往返；桌面测量包含渲染进程经本地桥到服务端的往返。结果不包含服务端到执行设备的 SSH 链路，也不代表模型首字或任务执行速度。当前窗口或标签页保留最近一次完整测试结果；连接变化后标记为上次连接，取消未完成测试不会覆盖旧结果。

## 构建与升级

完整仓库构建 Docker 镜像时，从 `apps/desktop` 构建同一套前端，只有生成的静态文件进入服务端运行阶段。Vite、Electron 和桌面开发依赖不进入运行镜像。

`npm run package:server` 每次重新构建当前前端，并将产物放进程序包的 `apps/server/web`。发布包既可用于 Docker 构建，也可由客户端发起原有服务端升级；运行时只安装服务端依赖。默认静态目录相对于**正在运行的程序**解析，因此更新不会继续引用旧镜像里的页面。

开发时可用以下环境配置连接本机已有服务；先运行 `npm run build`：

```dotenv
PROXY_WEB_ORIGIN='http://127.0.0.1:8787'
PROXY_WEB_DIR='apps/desktop/dist'
PROXY_HOST='127.0.0.1'
```

仅回环开发入口允许 HTTP。`PROXY_WEB_DIR` 用于显式覆盖静态目录；生产部署通常不需要设置它，避免升级后仍指向旧的静态文件。验证范围应区分自动化协议、登录与界面回归，和真实账号下的模型、审批、长任务及终端验收；本功能不以自动化回归代替真实模型验收。
