# 浏览器访问

浏览器直接连接现有服务端，与桌面共用页面和业务协议，不需要桌面中继或额外容器。
实现约定见 [服务端 Web 客户端](research/remote-access.md)。

## 启用

1. 在桌面客户端连接服务端，打开「设置 → 常规 → 浏览器访问」。
2. 开启「启用 Web 访问」，复制或打开显示的服务端地址。
3. 在浏览器输入部署时的服务凭据；开启两步验证后，还需要验证器的动态码。

Web 首次默认关闭。开关由桌面控制，服务端保存选择，重启后不重置。
关闭 Web 会断开浏览器连接，不影响桌面连接或已启动的模型运行；由浏览器打开的原生终端随连接关闭。
沿用服务端现有 HTTPS 端口和 Docker 映射；不提供公网明文 HTTP 开关。
仅本机回环开发环境允许 HTTP。

## 工作台

- 查看并操作在线设备上已有的会话：发消息、处理审批和问题、停止运行、打开终端。
- 新建普通会话时，执行环境是服务端容器，不是浏览器所在的电脑。
- 服务端会话归属稳定的「服务端」设备，不归属浏览器；退出、换浏览器或重启后仍能继续操作，桌面也能看到。
- 普通服务端会话各有自己的工作目录。主线已通过 #104 落实 #85 的项目对齐：同一设备、同一项目下的会话共享服务端工作目录、原生记忆和项目设置；已有原生上下文的会话移动或分叉后保留原目录，详见[原生运行与会话存储](native-runtime.md)。Web 不另建项目模型，第一版仍只新建普通服务端会话。
- 浏览器不提供本机目录、项目创建或移动、在其他设备上新建或分叉会话、附件上传、定时任务和客户端升级。

## 登录管理

服务凭据只用于登录和敏感操作的再次验证，不保存在浏览器本地存储。
登录后使用 `HttpOnly`、`Secure`、`SameSite=Strict` Cookie；服务端在现有 SQLite
数据库中保存会话秘密的哈希，不保存 Cookie 明文。更换服务凭据并重启后，旧浏览器登录失效。

默认无操作 2 小时退出，可在桌面设置中调整为 15 分钟至 24 小时；无论是否持续使用，
30 天后都需要重新登录。页面上的点击、按键、滚动和触摸，以及发消息、审批等操作会续期；
服务端推送的消息、自动刷新和断线重连不延长空闲时间。
「已登录浏览器」可单独撤销浏览器登录，撤销或退出会关闭对应连接。
桌面连接不生成浏览器登录记录。桌面端撤销无需再次验证；浏览器退出自己的登录也无需验证，
撤销其他登录则需再次验证：可使用通行密钥，或服务凭据及已启用的验证器动态码。
浏览器登录的失败次数与桌面连接分开计算：在浏览器里输错不会让同一出口地址的桌面无法连接。

推荐设置验证器两步验证。扫描二维码或手动输入密钥后，输入一次正确动态码才会启用。
桌面端直接显示二维码和密钥，无需重复输入服务凭据；从浏览器设置时仍需再次验证身份。
同一动态码不能重复使用；刚用它登录或确认操作后，请等待下一组动态码。
丢失验证器时，可通过已认证的桌面客户端关闭两步验证。第一版不提供恢复码。

## 通行密钥

通行密钥（Passkey）是浏览器的可选登录方式，桌面继续使用原有服务凭据连接。
先用服务凭据连接桌面、启用 Web，并设置固定访问域名及浏览器信任的 HTTPS 证书。
添加时，桌面连接也需使用这个域名对应的 HTTPS/WSS 入口，不从 IP 连接推断另一个站点的授权地址。
IP 直连和未受信任的自签入口仍使用原有登录方式；仅填写域名不会自动申请证书。
用户自行配置的 nginx/Caddy 同样支持：要求针对浏览器访问的公网入口，而不是内部上游。
公网证书可只放在反向代理，应用无须重复导入；已有 nginx 模式可以使用回环 HTTP 上游，
原 HTTPS 部署则可保留自签证书作为代理的受信上游。

在「设置 → 常规 → 浏览器访问」中添加通行密钥，填写识别名称。桌面会打开当前服务器的浏览器注册页，
用户确认后由系统或密码管理器完成指纹、面容或 PIN 验证；服务端登记成功才显示已添加。
注册页面使用五分钟有效的一次性授权，不携带服务凭据。取消、重启服务或改变入口后，未完成的授权失效。
从已登录的 Web 页面添加时，先再次验证身份，再在当前网站创建。

通行密钥用于 Web 登录。名称只是备注，不代表绑定某一台设备；
可添加多份密钥并重命名或删除。私钥由用户的认证器或密码管理器保存，服务端仅保存公钥和注册信息。
注册与登录均要求认证器验证用户身份；Passkey 登录不再要求服务凭据或验证器动态码。
原有 TOTP 仍只用于 Web 的服务凭据登录，不改变桌面原有连接规则。

通行密钥与两步验证、已登录浏览器一起放在「浏览器访问」中，开启 Web 后显示。

| 操作 | 影响 |
| --- | --- |
| 关闭 Web | 关闭浏览器入口并退出浏览器登录；保留已添加密钥，不影响桌面连接 |
| 修改访问路径 | 保留通行密钥，浏览器改用新地址重新登录；未完成的授权失效 |
| 更换访问域名 | 原域名的密钥标为不可用于当前域名，相关登录撤销；在新域名重新添加 |
| 删除通行密钥 | 同时撤销通过它建立的浏览器登录，不删除其他密钥 |
| 撤销一个浏览器 | 只撤销该登录，不删除通行密钥 |
| 更换服务凭据并重启 | 撤销全部已保存的 Web 登录，并移除通行密钥注册，防止旧授权继续访问 |

关闭页面或系统认证弹窗不表示注册成功。设备丢失时，可通过另一份通行密钥或原有服务凭据恢复访问，
再移除丢失的密钥及相关登录。服务端删除注册不等于删除密码管理器里的副本，后者由用户自行管理。

## 域名与路径

访问域名留空时使用部署地址；填写后，Web 只接受指定域名，其他域名或 IP 入口返回 404。
服务端访问路径默认留空，使用根路径；设置后整个 Web 入口移到该路径下，其他页面路径返回空的 404。
原有桌面 `/ws`、健康检查 `/health` 和安装包 `/client/installer` 入口保持原行为。

桌面端通过已认证的连接直接保存访问设置，无需重复输入服务凭据或动态码。
已登录浏览器也可修改路径，但仍需再次验证身份，可使用通行密钥，或服务凭据及已启用的动态码。
域名、空闲期限、可信代理和启停由桌面管理。域名或路径变更后，浏览器需要使用新地址重新登录。
自定义路径用于减少被扫描发现的机会，不代替登录鉴权。

## HTTPS 证书

自签部署下，浏览器会提示证书不受信任；请核对服务器，并改用正规证书或 HTTPS 反向代理。
登录页与工作台都会显示提示，证书在桌面「浏览器访问 → HTTPS 证书」中管理。
经已信任的反向代理访问时，浏览器拿到的是代理的证书，不显示这条提示。

直接 TLS 部署可以填写域名后，粘贴或选择 PEM 证书链及未加密私钥。
服务端校验证书格式、有效期、域名、私钥匹配和所提供链的签名，再为新 TLS 握手启用。
这不是完整的浏览器信任链验证；仍需浏览器信任签发机构，并提供有效的完整证书链。
界面显示签发者和有效期，到期前 30 天提示更换。

域名通过 SNI 使用导入的证书；IP 或不带域名的连接继续使用原默认证书。
同一域名的桌面连接也会使用导入证书，固定指纹的桌面连接需相应调整。
关闭 Web 不撤销已安装证书；修改或清空域名前，先恢复默认证书。

仅保存当前 `web/cert.pem` 和 `web/key.pem`，文件权限为 600，不保留旧私钥。
恢复默认会移除这两个文件，原默认证书不重新生成。导入仅在桌面提供，私钥不回传给页面。
第一版不自动申请或续期证书；使用 nginx/Caddy 时由反向代理管理证书。

## 反向代理

已有 nginx 部署模式保持原行为。直接 TLS 部署前增加反向代理时，可转发到现有 HTTPS 端口，
由代理信任服务端证书，无须增加监听端口。

默认不信任请求中的 `X-Real-IP`。需要按真实来源限制登录尝试时，在桌面访问设置中开启
「信任反向代理」，填写实际连接到服务端的代理 IP，只接受这些来源传来的地址头。
该来源是代理连接服务端时的出口地址：上游写服务器公网地址时，通常就是服务器自己的公网 IP；
Docker 中也可能是网桥网关地址，而不是 `127.0.0.1`。收到未受信任来源带来的地址头时，
访问设置会显示最近一次的来源地址；确认是自己的代理后再填写，不认识的地址不要加入。

桌面访问设置中的「反向代理配置示例」可生成 nginx 或 Caddy 片段。先保存访问域名、路径和
可信代理 IP，再核对示例中的上游地址。已有 nginx 模式使用回环 HTTP 上游；保留直接 TLS
部署时使用 HTTPS，并填写证书 SAN 校验名和反代机器上的信任 PEM 路径。选择 HTTP
只是生成已有部署对应的示例，不会切换服务端的 TLS 模式；后端 HTTP 只用于受隔离的内部连接。
这些字段只生成文本，不修改服务部署；上游应指向原服务地址，不能指回新反代域名造成循环。

自签部署使用安全复制出的公开证书作为信任文件，核对其 SHA-256 指纹与桌面连接一致；
CA 签发的上游使用相应根 CA 信任文件。不要复制私钥；指纹文本不能代替 PEM。
片段保留外部 Host（含非标准端口）、访问子路径及 WebSocket；HTTPS 上游校验证书，不关闭 TLS 校验。
自定义 Web 路径之外仍转发根路径的 `/ws` 与 `/client/installer`，供桌面登录和升级使用。
从桌面添加通行密钥时，桌面需连接外部域名及端口的 `/ws`，以生成当前站点的浏览器注册链接。
nginx 片段需要替换公网证书与私钥路径；Caddy 片段由 Caddy 管理公网证书。
复制后先执行 `nginx -t` 或 `caddy validate --config Caddyfile --adapter caddyfile`，通过后再重载。

## 部署包与边界

Docker 镜像和服务端升级包包含同版本前端，运行环境不需要 Electron 或 Vite。
从完整仓库安装、再用升级包升级时，镜像使用升级包内置的前端；之后改用 git 拉取更新的代码时，
`manage.sh` 发现源码比内置前端新，会改回从源码构建。
服务端会话中的 Claude Code 与服务程序使用同一系统用户，能读取服务配置。
处理外部内容时存在提示词注入导致凭据泄露的风险；独立系统用户或容器隔离是后续工作。
