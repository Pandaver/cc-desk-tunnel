# 服务端 Web 客户端（实验性）

浏览器直接连接现有服务端，使用与桌面客户端相同的页面、组件和业务协议。服务端提供静态页面和浏览器登录，不再托管桌面工作台的镜像，也不转发桌面的 HTTP 服务。

```text
浏览器 ── HTTPS / WSS ── 服务端 ── 现有执行通道 ── 目标设备
桌面端 ───── WSS ──────┘
```

浏览器和桌面独立选择会话、保存草稿和滚动位置；会话消息、审批和运行状态仍由服务端同步。关闭浏览器或退出浏览器登录不会关闭桌面客户端的连接。操作本地项目仍需要目标设备在线，不是脱离设备的纯云端执行。

## 当前支持

- 查看现有设备、项目与会话，以及会话消息和执行进度。
- 在已有会话中发送消息、回答问题、审批、停止，以及打开目标设备的原生终端。
- 与桌面共用界面和业务命令；浏览器不提供本机目录选择、执行通道、窗口管理和客户端升级等桌面宿主能力。

第一版不提供浏览器新建或移动项目、创建或分叉会话、附件上传和定时任务管理。它们需要明确的目标设备接口或文件传递机制，不通过让浏览器冒充执行设备实现。原桌面功能保持原有路径。

## 启用

Web 入口默认关闭，每次服务端启动后都需要在桌面设置中明确开启。关闭时不创建浏览器授权管理器、定时器或页面、登录、WebSocket 入口；普通桌面连接保持原有路径。不增加容器或监听端口；沿用现有服务端端口，默认 `8787`。

在部署数据目录的 `config/service.env` 中添加公开访问的**准确来源**，不要带结尾斜杠、路径、查询参数或用户凭据：

```dotenv
PROXY_WEB_ORIGIN='https://proxy.example.com'
```

首次配置来源后执行原有重启命令，让服务端具备 Web 访问能力：

```sh
sudo bash deploy/manage.sh restart
```

然后在已连接的桌面客户端中打开“设置 → 常规 → 浏览器访问”，开启“启用 Web 访问”。来源配置本身不会自动启用入口；日常开关无需重启服务端，不中断桌面连接或执行中的任务。未配置来源时不显示这块设置。

这里编辑的是数据目录的 `config/service.env`，不是程序目录的 `.local/docker.env`。入口地址用于核对浏览器来源，不负责申请证书、配置 DNS 或修改防火墙。公网与局域网访问要求浏览器信任的 HTTPS；可以沿用已有可信证书或 NGINX。桌面指纹连接的自签名证书不会自动成为浏览器信任的证书。

直接 TLS 模式可将来源设为 `https://proxy.example.com:8787`，并使用匹配该主机名的可信证书。NGINX 模式保持 `PROXY_TLS_MODE='reverse-proxy'`，容器端口仍仅绑定宿主回环地址。

### NGINX

先完成 [NGINX 部署](../deploy/nginx.md)。保留原有 `/ws`、`/client/installer` 和 `/health` 配置，在同一个 HTTPS `server` 中将原来返回 404 的 `location /` 替换为：

```nginx
location / {
    proxy_pass http://127.0.0.1:8787;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $cc_desk_tunnel_connection;
    proxy_set_header Host $http_host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
    proxy_buffering off;
}
```

`$cc_desk_tunnel_connection` 使用现有示例的 `map`。不要重写路径，也不要为浏览器入口开启跨域访问；页面、登录请求和 WebSocket 使用同一个来源与访问路径。通用 `location /` 保留 Upgrade 转发，因此桌面修改访问路径后不需要同步修改 NGINX 路由。

### 域名与访问路径

启用后，桌面设置显示服务端当前的“访问域名”和“服务端访问路径”。域名只填主机名，例如 `web.example.com`，不带协议、端口或路径；留空恢复部署来源。协议与公开端口仍由部署配置决定，公网入口继续使用 HTTPS。设置域名不会申请证书或配置 DNS，需要提前准备匹配域名的证书和解析。

首次启用会生成并保存随机访问路径，地址形如 `https://web.example.com/<访问路径>/`，不加固定 `/web/` 前缀。路径自动填入设置，可修改后移开焦点保存；留空则使用根路径 `https://web.example.com/`，也可使用刷新图标确认后重新生成。域名与路径保存期间，整组浏览器设置暂时禁用；失败时恢复已生效值。服务端访问地址随已保存的域名与路径更新：路径不超过 5 个字符时完整显示，超过时只显示前 5 个字符并追加 `...`，例如 `https://web.example.com/abcde...`；留空时显示根地址。复制和打开图标始终使用已生效的完整地址，公开端口保持不变。

页面、静态资源、登录接口及浏览器 WebSocket 全部位于该路径下。域名或路径不匹配时返回空白 `404`，不跳转到正确地址；这不改变桌面 `/ws`、安装包或健康检查的路由。访问路径只用于降低入口被发现的机会，配对和浏览器授权仍是实际访问控制。

修改访问地址会断开已有浏览器连接，旧地址立即失效，但不重置配对码或删除浏览器授权。只修改路径时，在同一来源打开新地址可继续登录；切换域名或端口后需要在新来源重新配对。桌面连接和会话任务不受影响，服务端重启后保留域名与路径，但入口仍默认关闭。

### 域名证书

直接 TLS 部署可以在桌面的“浏览器访问”中为访问域名设置自定义证书，无需 NGINX、新容器或额外端口。先填写访问域名，再打开证书设置，粘贴 PEM 格式的完整证书链和私钥，确认保存；两份内容一起校验，不在移开焦点时保存。证书必须处于有效期内、覆盖该域名，并与私钥匹配；服务端还会验证提交链的约束，拒绝链层级、名称约束或关键扩展不符合要求的证书。此验证不表示浏览器信任其签发者，自建 CA 仍需由访问设备信任。证书设置不是证书申请或自动续期，需要自行准备和更新证书。

服务端按 TLS 握手中的域名（SNI）选择证书：指定的 Web 域名使用自定义证书，IP、未发送 SNI 或其他域名继续使用原默认证书。原有 IP 加指纹的桌面连接和 Docker 健康检查不更换证书，端口仍与 Web 共用。**通过相同域名连接的桌面 `/ws` 也会使用自定义证书**；如该连接固定了旧证书指纹，应同步更新其指纹，或对受信任 CA 签发且域名匹配的证书使用原有 CA 校验模式。TLS 证书并不按 HTTP 路径区分。

证书管理仅对已认证的桌面客户端开放，浏览器授权不具备该权限。界面只显示证书的域名、签发者、有效期和指纹，私钥不回传、不存入浏览器本地数据。服务端以受限文件权限保存证书及私钥，校验或保存失败时保留原配置；新证书用于后续握手，不主动中断已建立的连接。

自定义证书使用期间，修改或清空访问域名前须先确认恢复默认证书；自定义访问路径不受此限制。恢复默认只撤销该域名的自定义证书，不重新生成原默认证书，也不删除浏览器授权。关闭 Web 入口仍保留该域名证书，避免改变同域名桌面连接的 TLS 身份；重启后证书设置保留，Web 页面入口仍默认关闭。已有自定义证书或可恢复的证书错误时，即使 Web 关闭也保留恢复默认入口，防止旧版本改过域名或恢复配置后无法启用；未使用证书功能的关闭状态不增加设置。证书扩展文件异常不阻止原代理服务启动，桌面设置显示相应状态。

反向代理部署显示“由反向代理管理”，证书继续由 NGINX、Caddy 等公网入口维护，应用内不提供证书导入。旧版服务端未声明证书管理能力时不显示新增设置。

## 登录与撤销

1. 使用已连接的桌面客户端，在设置中的“浏览器访问”开启入口，客户端会自动准备一次性配对码。
2. 复制服务端访问地址，在浏览器输入配对码；也可以直接使用桌面上的打开图标。
3. 开启入口或进入这块设置时，没有有效码就自动生成；已有有效码直接复用，不延长其有效期。配对码有效期 5 分钟，使用一次后失效。浏览器取得独立登录，不接收或保存服务凭据 `PROXY_TOKEN`；服务端不设置登录自动过期。
4. 在桌面的“已登录浏览器”中可以展开列表并单独撤销；配对、退出、撤销与码失效会同步更新，不需要反复刷新。退出登录、撤销或浏览器清理登录数据后需重新配对；退出或撤销也会关闭已经建立的浏览器连接。

配对码只在明确进入设置或启用入口时按需准备，不在后台循环续码。生成失败会显示错误，重试由用户发起；手动重新生成仍需确认。

浏览器登录代表对该服务端已有会话的操作权限，不是仅限于生成配对码的那台桌面。请只给自己的可信浏览器配对。Cookie 为 `HttpOnly`、同站点且在 HTTPS 下使用 `Secure`；服务端只保存登录凭据的哈希。登录、退出和 WebSocket 握手检查来源，失败配对限速；桌面服务凭据认证路径保持不变。

关闭“启用 Web 访问”会立即停止整个服务端的浏览器入口、断开浏览器连接并清除未使用的配对码，不影响原有桌面连接和会话任务。浏览器打开的原生终端随连接关闭，桌面端的终端不受影响。配置、项目、会话和浏览器授权记录仍保留；浏览器遇到入口返回 `404` 后会停止自动重连；重新开启后刷新原地址，未撤销且仍保留登录数据的浏览器可继续使用，无需重新配对。所有已打开该设置的桌面同步开关与授权状态，配对码只发送给生成它的桌面设备。服务端重启后入口恢复关闭，需要再次明确启用。

Web 配置或授权文件读取失败只会让本次启用失败，不阻止普通代理服务启动。取消 `PROXY_WEB_ORIGIN` 并重启可移除该可选能力。旧版服务端只有部署时开关时，客户端保留其原有配对管理入口，不显示不受支持的动态开关；未声明幂等初始化能力的服务端仍使用手动生成，避免重置已有配对码；未声明地址设置能力的服务端不显示域名与路径输入。

## 连接诊断

支持诊断的服务端会在桌面和浏览器的标题栏提供“连接诊断”入口。手动测试通过当前已认证的 WebSocket 连续采样 5 次，以中位数显示服务往返耗时；展开详情可查看每次采样、最小值、最大值及超时或失败次数。不会定时或在后台自动测试。

浏览器测量的是浏览器到服务端的往返；桌面测量包含渲染进程经本地桥到服务端的往返。结果不包含服务端到执行设备的 SSH 链路，也不代表模型首字或任务执行速度。当前窗口或标签页保留最近一次完整测试结果；连接变化后标记为上次连接，取消未完成测试不会覆盖旧结果。

## 构建与升级

完整仓库构建 Docker 镜像时，从 `apps/desktop` 构建同一套前端，只有生成的静态文件进入服务端运行阶段。Vite、Electron 和桌面开发依赖不进入运行镜像。

`npm run package:server` 每次重新构建当前前端，并将产物放进程序包的 `apps/server/web`。发布包既可用于 Docker 构建，也可由客户端发起原有服务端升级；运行时只安装服务端依赖。默认静态目录相对于**正在运行的程序**解析，因此更新不会继续引用旧镜像里的页面。

开发时可用以下环境配置连接本机已有服务；先运行 `npm run build`：

```dotenv
PROXY_WEB_ORIGIN='http://127.0.0.1:8787'
PROXY_WEB_DIR='apps/desktop/dist'
PROXY_HOST='127.0.0.1'
```

仅回环开发入口允许 HTTP。`PROXY_WEB_DIR` 用于显式覆盖静态目录；生产部署通常不需要设置它，避免升级后仍指向旧的静态文件。验证范围应区分自动化协议、登录与界面回归，和真实账号下的模型、审批、长任务及终端验收；本功能不以自动化回归代替真实模型验收。
